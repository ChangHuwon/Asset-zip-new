# 온보딩: 가족 그룹 생성 & 합류

## 배경

Asset.ZIP은 이메일 회원가입 없이, 가족만 아는 초대코드로 간단히 들어오는 방식을 쓴다 (복잡한 계정 시스템보다 진입장벽을 낮추는 것이 우선).

## 형식 (테스트 케이스 작성을 위해 구체적으로 고정)

- **초대코드**: 8자 영숫자 (혼동되는 문자 0/O, 1/l/I는 제외). 예: `7F3KQXM9`. 화면에 표시할 때는 FRONTEND.md 컴포넌트 매핑의 "초대코드 칩"(`button-pill-rausch`, `rounded.full`) 스타일을 쓴다.
- **PIN**: 숫자 4자리로 통일한다 (SECURITY.md의 rate limit 설계도 이 자리수를 전제로 한다). 입력 필드는 FRONTEND.md 컴포넌트 매핑의 "계좌 입력 폼"과 같은 `text-input` 토큰을 공유한다.
- **표시 이름**: 같은 가족 그룹 안에서는 중복될 수 없다. 재방문 로그인(플로우 3)이 "표시 이름을 목록에서 선택"하는 방식이라, 이름이 겹치면 어떤 사람인지 구분할 수 없어 로그인 자체가 불가능해진다. 합류 시(플로우 2) 이미 쓰이는 이름이면 "이미 사용 중인 이름입니다 — 다른 이름(예: '아빠2', '엄마_큰딸')을 입력해주세요"처럼 즉시 안내하고 다른 이름을 받는다.

## 플로우 1 — 가족 그룹 최초 생성

1. 최초 사용자가 "가족 그룹 만들기"를 선택한다.
2. 그룹 이름(예: "우리집")을 입력한다.
3. 시스템이 위 형식의 초대코드를 발급한다 (SECURITY.md 기준).
4. 생성자는 자신의 표시 이름과 4자리 PIN을 설정해 첫 번째 구성원으로 등록된다.
5. 초대코드를 다른 가족 구성원에게 공유(카카오톡 등 외부 채널로 직접 전달 — 앱 내 초대 발송 기능은 MVP 범위 밖)한다.

## 플로우 2 — 가족 구성원 합류

1. 새 사용자가 초대코드를 입력한다.
2. 유효한 코드면 그룹 이름이 확인 화면에 표시된다 ("우리집에 합류하시겠습니까?").
3. 표시 이름과 4자리 PIN을 설정하면 해당 가족 그룹의 구성원으로 등록된다 (표시 이름은 그룹 내에서 유일해야 한다 — 위 "형식" 절 참고).

## 플로우 3 — 로그인 (재방문)

1. **기기가 이전에 로그인한 적이 있다면 자동 로그인된다** (세션을 기기에 저장 — 초대코드/PIN 재입력 없이 바로 대시보드로 진입). "부담 없이 자주 열어보는 도구"라는 PRODUCT_SENSE.md의 지향점과, "실용적 수준의 보안이면 충분하다"는 core-beliefs.md 2번 원칙에 따른 선택이다. 로그아웃을 명시적으로 누르거나 다른 구성원으로 전환할 때만 다시 인증한다.
2. 세션이 없는 새 기기라면 초대코드를 입력해 그룹을 찾고, 본인의 표시 이름을 선택한 뒤 PIN을 입력해 로그인한다.
3. 로그인 시도 실패가 반복되면 기본적인 rate limit이 적용된다 (SECURITY.md 참고).

## 예외 처리

- 잘못된 초대코드 입력 시: 코드가 유효하지 않다는 안내만 하고, 어떤 부분이 틀렸는지(그룹 존재 여부 등)는 노출하지 않는다.
- PIN 분실 시: 가족 내 다른 구성원(관리자 역할 구분은 없으므로 아무 구성원)이 재설정을 도와주는 방식으로 처리한다. (자동화된 PIN 복구는 백로그)
- **알려진 제약**: 가족 구성원이 1명뿐이고 그 사람이 PIN을 분실하면 MVP 단계에서는 복구 수단이 없다 (계정을 새로 만들어야 함). 저장 데이터 자체가 사라지는 것은 아니지만 접근이 막힌다. 이 앱의 낮은 보안 위협 수준(core-beliefs.md 2번 원칙)을 고려할 때 수용 가능한 리스크로 간주하고, MVP 단계에서는 별도 복구 플로우를 만들지 않는다.

## 범위 밖

- 이메일/전화번호 인증
- 소셜 로그인
- 앱 내 초대 발송(문자/이메일 자동 발송)
