# Core Beliefs

Asset.ZIP이 어떤 결정 앞에서든 흔들리지 않고 따라야 할 원칙들이다. 새로운 기능을 검토하거나 기술적 트레이드오프를 고민할 때, 이 문서와 충돌하는 방향이라면 그 방향이 틀린 것이다.

## 1. 공동자산만 다룬다 — 개인 프라이버시 설계는 필요 없다

Asset.ZIP은 가족이 "함께 보기 위해" 만드는 도구다. 개인 명의 계좌나 개인 자산은 애초에 이 앱의 대상이 아니다. 따라서 "누가 무엇을 볼 수 있는가"를 세밀하게 통제하는 권한 시스템은 만들지 않는다. 가족 초대코드로 들어온 사람은 전체 공동자산을 볼 수 있다. 이 전제가 바뀌지 않는 한(예: 나중에 개인 자산 트래킹이 추가된다면) 권한 모델은 지금처럼 단순하게 유지한다.

## 2. 보안은 실용적인 수준이면 충분하다

Asset.ZIP은 은행 계좌 인증정보나 공동인증서, 실명 같은 민감정보를 절대 저장하지 않는다. 저장하는 것은 오직 "얼마"라는 숫자와 카테고리뿐이다. 이 데이터가 유출되더라도 피해는 "가족의 대략적인 자산 규모가 노출되는 것" 정도로 제한적이다.

그래서:
- 금융권 수준의 암호화, 침투 테스트, 보안 감사는 하지 않는다.
- 다만 초대코드/PIN은 기본적인 무차별 대입 공격 정도는 막아야 한다 (SECURITY.md 참고).
- Vercel, Railway 등 관리형 플랫폼이 기본으로 제공하는 보안(HTTPS, 인프라 패치)에 의존하고, 그 이상을 직접 구축하지 않는다.

## 3. 수동 입력이 먼저다 — 자동 연동은 나중 문제

오픈뱅킹 연동이나 스크래핑은 정확성 문제, 인증 복잡도, 유지보수 부담을 동반한다. 초기 버전은 가족 구성원이 직접 숫자를 입력하는 방식으로 시작하고, 이 방식이 충분히 검증된 뒤에만 자동 연동을 고려한다. "얼마나 자동화되어 있는가"보다 "지금 화면에 보이는 숫자를 얼마나 믿을 수 있는가"가 훨씬 중요하다.

## 4. 모든 금액은 원화로 정규화한다

해외주식처럼 외화로 표시되는 자산도 입력 시점에 원화로 환산해 저장한다. 대시보드는 항상 하나의 통화(KRW)로 통일된 총액을 보여준다. 통화별로 따로 표시하고 나중에 합산하는 방식은 복잡도만 늘리고 "우리 가족 자산이 지금 총 얼마인가"라는 핵심 질문에 즉답을 주지 못한다.

## 5. 빠르게 반복 가능한 캐주얼 툴이다

Asset.ZIP은 사내 프로덕트도, 유료 SaaS도 아니다. 가족 몇 명이 쓰는 내부용 도구다. 완벽한 테스트 커버리지, CI/CD 파이프라인, 24/7 모니터링 같은 무거운 엔지니어링 관행을 강제하지 않는다. 대신 "돈 계산이 틀리지 않는 것"과 "빠르게 고치고 다시 배포할 수 있는 것"에 집중한다. (RELIABILITY.md, QUALITY_SCORE.md 참고)
